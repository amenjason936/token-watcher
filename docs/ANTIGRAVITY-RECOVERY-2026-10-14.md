# Antigravity 用量修复与升级恢复说明

1.9.2 的 Antigravity 采集版本由 v2 升至 v3。新版本首次运行会重新读取仍在本机的日志，并按同一会话与步骤键补正已有记录；这可能使历史 token 和费用明显变化。真实 usage 可以缩减或增加旧估算，重复扫描不会增加同一事件。

## 升级前备份

1. 暂停正在采集的 token-watcher 实例，确认没有第二个进程打开同一统计库。
2. 为 `~/.tokenmeter/tokenmeter.db` 生成一致的 SQLite 备份，建议使用 SQLite backup API。活库 WAL 模式下不要只拷贝主 .db 文件。
3. 验证备份 `PRAGMA quick_check` 返回 ok，并记录备份时间和 SHA-256。保留原始 Antigravity 日志；备份和个人恢复材料留在本机。
4. 安装 `token-watcher@1.9.2` 并重新启动原来的单个服务实例，等待 v3 重扫完成。

已完成 v3 历史回填的本机无需再人工重扫。普通升级由版本机制触发仍存在文件的重扫；无法重新读取的历史日志不能凭空恢复。

## 变更与验收

- 新版 CLI 优先使用每轮 input_tokens、cache_read_tokens、output_tokens；输入不含缓存，输出包含思维，总量计入缓存而不重复加思维。
- 旧日志按完整 metadata 上下文或完整字符上下文估算，不再使用相邻轮差分。旧输出仍为估算。
- usage_quality=3 为真实 usage、2 为 metadata 上下文与估算输出、1 为字符估算、0 为尚未分类的旧记录；估算不能覆盖实数。
- 常规/full/重放日志共用会话与步骤键，ACTIVE 不抢占 DONE，晚到最终字段可以补登。
- metadata 晚到时逐事件补正；transcript 不变也会重试 pending，仅更新已有事件时仍通知面板刷新。

用固定原始日志的会话与步骤键逐字段对账，确认缓存读已计入、思维未重复；再次扫描应新增零事件、已有总量不变。检查健康面板无解析错误，并确认其他来源账本保持正常。旧日志无真实字段时，usage_quality 保留估算，不能提升为实数。

完整隔离回归 820 项通过，包含实数/旧估算、metadata 时序、去重和模型价格测试。模型价格优先级为用户价格 → 已核实官方价 → LiteLLM；Argon 与 Gemini 3.8 Flash 内部别名已覆盖。免费名称与缺价名称分别处理，详见 [价格核对](MODEL-PRICING-AUDIT-2026-10-14.md)。

## 回退

暂停所有打开统计库的服务，以已校验的一致备份通过 SQLite backup API 恢复统计库，然后启动对应旧版本。回退统计结果时须同时回退采集逻辑；否则 v3 会再次核算现存日志。恢复备份会回退备份后的新增用量，执行前应保留当前一致快照。

升级恢复本地 token 历史，不会自动补报社区排行榜过去日期，也不确定 Google 账号额度或实付账单。
